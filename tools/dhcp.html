DHCP und ip helper-address

Ein PC ohne IP-Adresse ruft per Broadcast nach einem DHCP-Server. Steht der Server in einem anderen Netz, bleibt dieser Ruf am Router hängen – außer, der Router ist mit ip helper-address als DHCP-Relay eingerichtet.

Der DHCP-Ablauf: Discover, Offer, Request, Ack

Das Paket in diesem Moment

Wo kommt ip helper-address hin – und was steht dahinter?

Wo?

  • Auf dem Router-Interface, an dem die Clients hängen – also dort, wo ihr Broadcast ankommt.
  • Das ist das Interface, dessen IP die Clients als Gateway haben (bei VLANs: das Subinterface bzw. die SVI des VLANs).
  • Nicht auf dem Interface Richtung Server, nicht auf Routern dazwischen.
  • Für jedes Client-Netz ohne eigenen DHCP-Server ein Helper.

Was dahinter?

  • Die IP-Adresse des DHCP-Servers – das Ziel ganz am Ende des Weges.
  • Nicht der nächste Router, nicht das Gateway des Server-Netzes, keine Broadcast-Adresse.
  • Der Router schickt den Broadcast als Unicast an diese IP – normal geroutet, über beliebig viele Router.
interface GigabitEthernet0/0
 ip address 192.168.10.1 255.255.255.0
 ip helper-address 10.0.0.10

Woher weiß der Server, welcher Pool?

  • Der Relay trägt seine Interface-IP als giaddr (Gateway-Adresse) ins Paket ein: 192.168.10.1.
  • Der Server sucht den Pool, in dessen Netz giaddr liegt → 192.168.10.0/24.
  • Die Antwort geht an giaddr zurück – der Server braucht also eine Route zum Client-Netz.

Merksatz

Helper sitzt bei den Clients – und zeigt auf den Server.

Ist ein Router selbst der DHCP-Server, braucht sein eigenes Client-LAN keinen Helper. Die anderen Router zeigen mit dem Helper auf eine IP dieses Routers.

Regelwerk

Router als DHCP-Server

ip dhcp excluded-address 192.168.10.1 192.168.10.10
ip dhcp pool LAN10
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 8.8.8.8
  • excluded-address: Adressen, die nicht vergeben werden (Gateway, Server, Drucker).
  • default-router: das Gateway der Clients – die Router-IP in ihrem LAN, nicht die IP des DHCP-Servers.

Die vier Pakete

  • DDiscover – Client: „Gibt es einen DHCP-Server?“ (Broadcast)
  • OOffer – Server: „Nimm 192.168.10.11.“
  • RRequest – Client: „Ich nehme sie.“ (wieder Broadcast)
  • AAck – Server: „Bestätigt.“ Ab jetzt gilt die Adresse.

UDP: Client Port 68, Server Port 67. Der Client hat anfangs die IP 0.0.0.0.

Nachschauen

show ip dhcp binding
show ip dhcp pool
show running-config | include helper

Am Windows-PC: ipconfig /release und ipconfig /renew starten den Ablauf neu, ipconfig /all zeigt DHCP-Server und Lease.

Typische Fehler

  • Helper auf dem Interface Richtung Server statt bei den Clients.
  • Hinter dem Helper die IP des nächsten Routers statt des Servers.
  • default-router = IP des DHCP-Servers – falsch, es ist das Gateway der Clients.
  • Kein Pool für das Client-Netz, oder keine Route vom Server zurück.

Übungen

Alle Clients sollen ihre Adresse vom DHCP-Server bekommen. Hake im Plan die Interfaces an, auf denen ip helper-address konfiguriert werden muss, und beantworte die Fragen darunter.
