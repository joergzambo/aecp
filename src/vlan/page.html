VLANs und Trunking

Ein VLAN teilt einen Switch in mehrere getrennte Netze. Ein Broadcast bleibt in seinem VLAN. Über einen Trunk laufen mehrere VLANs gleichzeitig, jeder Frame bekommt dafür einen 802.1Q-Tag mit seiner VLAN-Nummer.

Regelwerk

Access-Port

  • gehört zu genau einem VLAN
  • Frames gehen ohne Tag zum PC – der PC weiß nichts vom VLAN
interface Fa0/1
 switchport mode access
 switchport access vlan 10

Trunk-Port

  • transportiert mehrere VLANs zwischen Switches
  • jeder Frame bekommt einen 802.1Q-Tag (4 Byte) mit der VLAN-ID (12 Bit → VLAN 1–4094)
  • ein VLAN muss auf beiden Seiten erlaubt sein
interface Gi0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20
 switchport trunk native vlan 99

Native VLAN

  • Frames im native VLAN laufen ohne Tag über den Trunk (Standard: VLAN 1)
  • ein ungetaggter Frame landet auf der anderen Seite in deren native VLAN
  • sind die native VLANs verschieden (Mismatch), springen Frames in ein fremdes VLAN – Cisco meldet dann „Native VLAN mismatch“
  • Empfehlung: ungenutztes VLAN wie 99 als native VLAN

Zwischen VLANs

  • jedes VLAN ist ein eigenes IP-Netz und eine eigene Broadcast-Domäne
  • PCs in verschiedenen VLANs erreichen sich nur über einen Router oder Layer-3-Switch (Inter-VLAN-Routing)
  • prüfen mit show vlan brief und show interfaces trunk
So löst du die Aufgaben: Starte beim Sender in seinem VLAN. Der Broadcast erreicht alle PCs im selben VLAN am selben Switch. Über einen Trunk geht er nur, wenn das VLAN auf der sendenden Seite erlaubt ist; dort bekommt er einen Tag (außer im native VLAN). Auf der Empfängerseite muss das VLAN ebenfalls erlaubt sein. Ein Frame ohne Tag landet im native VLAN der Empfängerseite.

Übungen

Kreuze an und klicke auf „Prüfen“. Die Lösung zeigt den Weg des Broadcasts mit allen Tags.
