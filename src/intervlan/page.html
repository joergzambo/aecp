Inter-VLAN-Routing

Jedes VLAN ist ein eigenes IP-Netz. Damit PCs aus verschiedenen VLANs miteinander reden können, braucht es einen Router oder einen Layer-3-Switch. Er ist das Gateway jedes VLANs und leitet die Pakete von einem Netz ins andere weiter.

Regelwerk



 
Router-on-a-Stick
    
  
  • ein physisches Router-Interface, darauf ein Subinterface pro VLAN
    • 
  
  • encapsulation dot1Q muss genau die VLAN-Nummer sein
    • 
  
  • die IP des Subinterfaces ist das Gateway der PCs im VLAN
    • 
  
  • der Switchport zum Router ist ein Trunk mit allen VLANs

  
interface Gi0/0
 no shutdown
interface Gi0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0

 
Layer-3-Switch
    
  
  • pro VLAN ein virtuelles Interface (SVI): interface Vlan10
    • 
  
  • die SVI-IP ist das Gateway der PCs
    • 
  
  • ip routing einschalten – sonst wird nicht geroutet
    • 
  
  • kein Trunk zum Router nötig, schneller (Routing in Hardware)

  
ip routing
interface Vlan10
 ip address 192.168.10.1 255.255.255.0
 no shutdown

 
Was sich unterwegs ändert
    
  
  • IP-Adressen bleiben gleich – Quelle und Ziel von Anfang bis Ende
    • 
  
  • MAC-Adressen ändern sich am Router: neue Quell-MAC (Router), neue Ziel-MAC (Empfänger)
    • 
  
  • VLAN-Tag wechselt von 10 auf 20
  • der Router zieht 1 von der TTL ab

 
Was der PC entscheidet
    
  
  • liegt das Ziel laut eigener Maske im eigenen Netz? → direkt per ARP
    • 
  
  • sonst → ans Default-Gateway (muss im eigenen Netz liegen)
    • 
  
  • eine falsche Maske kann den PC glauben lassen, das Ziel sei „nebenan“




Fehlersuche – so gehst du vor: Verfolge den Hinweg: Maske und Gateway des Senders → Access-Port im richtigen VLAN → Trunk lässt das VLAN durch → Subinterface/SVI mit passender VLAN-Nummer und Gateway-IP → Router kennt das Zielnetz → raus ins richtige VLAN. Dann dasselbe für den Rückweg – ein Ping braucht beide Richtungen!
