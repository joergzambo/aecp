Routing-Schleifen: Count to Infinity, Split Horizon und Route Poisoning

Distanzvektor-Protokolle wie RIP kennen das Netz nur vom Hörensagen: Jeder Router glaubt, was ihm der Nachbar erzählt. Fällt ein Netz aus, kann das zu einer Schleife führen, in der die Router sich gegenseitig immer schlechtere Wege einreden – bis 16 Hops. Drei Tricks verhindern das.

Die Schutzmechanismen

MechanismusRegelWas er bewirkt
Maximaler Hop-Count16 Hops = unerreichbarBeendet Count to Infinity spätestens bei 16 – die Schleife hört auf, dauert aber lange.
Split HorizonEine Route wird nicht über das Interface zurück angekündigt, über das sie gelernt wurde.R2 erzählt R1 nichts über das Netz, das er von R1 kennt. Die Schleife zwischen zwei Nachbarn kann gar nicht entstehen.
Route PoisoningFällt ein Netz aus, wird es sofort mit Metrik 16 angekündigt (Triggered Update).Alle erfahren schnell und ausdrücklich: „Dieses Netz ist tot“ – statt auf Timer zu warten.
Poison ReverseAusnahme von Split Horizon: Die vergiftete Route wird mit 16 zurückgeschickt.Bestätigt dem Absender: „Verstanden, ich nutze dich nicht mehr für dieses Netz.“
Hold-Down-TimerNach einer „unerreichbar“-Meldung werden schlechtere Angebote für das Netz eine Zeit lang (RIP: 180 s) ignoriert.Alte, veraltete Updates können die tote Route nicht wiederbeleben.

Split Horizon schützt nur zwischen zwei Nachbarn. In Ringen aus drei und mehr Routern kann trotzdem eine Schleife entstehen – dort helfen Route Poisoning und Hold-Down. Bei Cisco ist Split Horizon auf den meisten Interfaces standardmäßig an (ip split-horizon).

R1(config)# interface Gi0/1
R1(config-if)# ip split-horizon          ! Standard – so lassen
R1(config-if)# no ip split-horizon       ! nur in Sonderfällen (z. B. Hub-and-Spoke)
