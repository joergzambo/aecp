Layer-3-Switching

Ein Layer-3-Switch ist Switch und Router in einem Gerät. Innerhalb eines VLANs switcht er wie jeder Switch anhand der MAC-Tabelle. Zwischen VLANs routet er anhand seiner Routing-Tabelle – in Hardware, ohne externen Router und ohne Trunk-Engpass.

Regeln und Befehle



 
SVI – das Gateway eines VLANs
    
  
  • interface Vlan10 ist ein virtuelles Layer-3-Interface für das ganze VLAN 10.
    • 
  
  • Ihre IP-Adresse ist das Standardgateway der PCs in diesem VLAN.
    • 
  
  • Damit zwischen den SVIs geroutet wird, braucht es ip routing.

  
DSW1(config)# ip routing
DSW1(config)# interface vlan 10
DSW1(config-if)# ip address 192.168.10.1 255.255.255.0
DSW1(config-if)# no shutdown

 
Routed Port – der Uplink zum Router
    
  
  • no switchport macht aus einem physischen Port ein Router-Interface.
    • 
  
  • Er gehört zu keinem VLAN, bekommt direkt eine IP (meist ein /30) und schickt Frames ohne Tag.
    • 
  
  • Ohne no switchport lehnt der Switch ip address ab.

  
DSW1(config)# interface g1/0/24
DSW1(config-if)# no switchport
DSW1(config-if)# ip address 10.0.0.2 255.255.255.252

 
Wann ist eine SVI up / up?
    
  
  • Das VLAN existiert in der VLAN-Datenbank (vlan 10).
    • 
  
  • Mindestens ein Port im VLAN ist aktiv (Access-Port mit Gerät oder ein Trunk, der das VLAN führt).
    • 
  
  • Die SVI ist nicht mit shutdown abgeschaltet.

  
Abgeschaltet → administratively down / down. VLAN fehlt oder kein aktiver Port → up / down. Nur Netze von SVIs mit up / up stehen als C in der Routing-Tabelle. Achtung: In show running-config steht nur shutdown, wenn ein Interface abgeschaltet ist – no shutdown ist der Normalfall und wird nicht angezeigt.

 
Raus ins Internet – und wieder zurück
    
  
  • Der Switch kennt nur seine direkt verbundenen Netze. Für alles andere: Default-Route zum Router.
    • 
  
  • Der Next Hop muss in einem direkt verbundenen Netz liegen, sonst landet die Route nicht in der Tabelle.
    • 
  
  • Der Router braucht den Rückweg zu den VLAN-Netzen – einzeln oder zusammengefasst.

  
DSW1(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.1
R1(config)# ip route 192.168.0.0 255.255.0.0 10.0.0.2




Uplink als Trunk – VLANs zum Router durchreichen


Statt eines Routed Ports wird der Uplink oft ein Trunk. Das hat zwei Gründe:


1. Transit-VLAN statt Routed Port
    

  • Eigenes VLAN (z. B. 99) nur für die Strecke Switch ↔ Router, mit /30-Netz.
    • 

  • Switch: SVI Vlan99, Router: Subinterface Gi0/0.99 mit encapsulation dot1Q 99.
    • 

  • Stolpersteine: VLAN 99 anlegen, auf dem Trunk erlauben, gleiche dot1Q-Nummer auf beiden Seiten.


2. VLANs am Switch vorbei zum Router
    

  • Für manche VLANs (Gäste, DMZ, Server hinter der Firewall) gibt es keine SVI am Switch.
    • 

  • Das VLAN läuft über den Trunk zum Router oder zur Firewall – dort ist das Gateway (Router-on-a-Stick nur für diese VLANs).
    • 

  • So geht dieser Verkehr immer über die ACLs bzw. Firewall-Regeln.


DSW1(config)# vlan 99
DSW1(config-vlan)# name Transit
DSW1(config)# interface g1/0/24
DSW1(config-if)# switchport mode trunk
DSW1(config-if)# switchport trunk allowed vlan 30,99
DSW1(config)# interface vlan 99
DSW1(config-if)# ip address 10.0.0.2 255.255.255.252
DSW1(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.1

R1(config)# interface g0/0.99
R1(config-subif)# encapsulation dot1Q 99
R1(config-subif)# ip address 10.0.0.1 255.255.255.252
R1(config)# interface g0/0.30
R1(config-subif)# encapsulation dot1Q 30
R1(config-subif)# ip address 192.168.30.1 255.255.255.0


Wichtig: Jedes VLAN hat genau ein Gateway – SVI am Switch oder Subinterface am Router. Und: Ein Trunk, der ein VLAN führt, zählt als aktiver Port dieses VLANs. Bei switchport trunk allowed vlan all bleiben deshalb alle SVIs up / up, auch wenn kein PC im VLAN eingesteckt ist. Mit einer Liste erlaubter VLANs ist das sauberer.
